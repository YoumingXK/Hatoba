## Hatoba 0.4.0 — Bitwarden's SSH agent and Touch ID

This build of this fork is upstream 0.3.0 with everything merged since — the grep match counting and
`run_command` directory fixes among them — plus two features that are still open upstream.

**Bitwarden's SSH agent.** Hatoba finds the agent of this device itself: the socket you name in
Settings → SSH Agent, then `SSH_AUTH_SOCK`, then a known one (Bitwarden, 1Password, GnuPG, GNOME
keyring). A Bitwarden vault unlocked in the Bitwarden desktop app can therefore hold your SSH keys,
with no environment variable to set. On Windows it is the OpenSSH agent or Bitwarden's named pipe.

**Unlock with Touch ID on macOS.** Settings → Security offers it on a Mac with Touch ID: the master
password once, then the system's own sheet, and the lock screen then asks for a fingerprint on its
own once per lock. The key never leaves the Secure Enclave, and the record Hatoba keeps beside
`vault.db` (mode 0600) is worth nothing on another Mac. A Mac whose lid is closed cannot read a
fingerprint, and the app says that your identity cannot be verified right now rather than reporting
a cancellation; the master password is always there.

The macOS build is ad-hoc signed and not notarized, as upstream's own is, so the first open needs
**Open Anyway** under **System Settings → Privacy & Security**.
